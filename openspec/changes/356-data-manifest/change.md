# Change: 356-data-manifest

**SDD change**: `356-data-manifest`
**Date**: 2026-10-03
**Status**: Applied
**Tracking issue**: see sibling `issue.md` (#356)

Mirror of engram topic key `sdd/356-data-manifest/change` (see
[ADR-009 §6](../../../docs/architecture/adr-009-documentation-strategy.md#6-change-specs--sdd-artifacts-dual-source-convention)
dual-source rule).

## Summary

Pre-registration v1 §4 promises a `data-manifest.json` that fingerprints every dataset behind a certification
result, and says the code refuses OOS reads outside certification. Neither exists in `src/` today: the ingest
manifest (`<data-dir>/manifests/data-manifest.json`) hashes downloaded zip files, not the bars a backtest consumes,
and `DataSplitEnforcer` has no production caller. This change adds a dataset-level manifest (one entry per pair,
interval and split, with row count and a content hash over the parsed bars), a loader that verifies every bar it
hands a backtest against that manifest and refuses OOS entries unless the certification lifecycle allows it, and
wires the loader into `scripts/backtest/run_calibration.py`. Train and Validation entries are pinned from the local
archive in this change; OOS entries are added only at certification. Main risk: the content hash depends on a
canonical bar serialisation, so any change to it invalidates every pinned entry (D-2).

## Scope

### In

- `domain/market_data/dataset_manifest.py`: `DataSplit`, `SplitWindow`, `DatasetEntry`, `DatasetManifest`,
  `bars_content_sha256`.
- `domain/errors.py`: `DatasetHashMismatchError`, `DatasetNotPinnedError`.
- `ports/dataset_manifest.py`: `DatasetManifestPort`.
- `adapters/data_manifest/json_file.py`: JSON file adapter (load and write).
- `application/strategy_protocol/pinned_dataset.py`: `load_pinned_bars`, `pin_dataset`,
  `assert_oos_access_allowed`, `assert_manifest_matches_preregistration`.
- `application/strategy_protocol/data_split_enforcer.py`: `certification_context()` becomes class-based. The
  generator version turned any frozen `DomainError` raised inside the block into `FrozenInstanceError`, so a refused
  or mismatched read during certification would have crashed with the wrong error.
- `scripts/data/build_dataset_manifest.py`: builds Train and Validation entries from `HERMES_DATA_DIR`.
- `docs/experiments/swing-mvp1/data-manifest.json`: the pinned manifest (path named by pre-registration §4), 12
  entries: BTC, ETH and SOL at 4h and 1d, Train and Validation.
- `scripts/backtest/run_calibration.py`: loads bars through `load_pinned_bars`; the report records each dataset id
  and hash it used.

### Out

- Trial records referencing the manifest: #357 (they will carry the `datasets` list this change adds to the report).
- Persisted certification state and `hermes certify`: #355. Until then the driver runs as `UNTRUSTED`, so OOS is
  always refused.
- OOS entries: pinned at certification, on or after 2027-01-01.
- 1h datasets: the archive's `BTCUSDT-1h-2020-12.zip` has a row whose close time precedes its open time, which the
  adapter rejects. The backtest driver does not read 1h, so 1h stays unpinned until that row is repaired.

## Decisions

### D-1: Dataset-level entries per (pair, interval, split), not per archive file

- **Decision**: An entry covers one pair and interval over one whole split window.
- **Alternatives**: Reuse the ingest manifest's per-zip hashes (proves the download, not the bars the strategy saw;
  a parser change would go unnoticed). One entry per month (≈ 400 entries, no gain for the checks this issue needs).
- **Rationale**: The split is the unit pre-registration §4 controls access by, and the bars are what a result
  depends on.
- **Cost of reversal**: LOW — the manifest is regenerated by the builder script.

### D-2: Content hash over a canonical serialisation of parsed bars

- **Decision**: SHA-256 over one line per bar, sorted by `open_time`:
  `BASE/QUOTE|interval|open_time ISO|open|high|low|close|volume|close_time ISO`, Decimals as
  `format(d.normalize(), "f")`.
- **Alternatives**: Hash the raw zip bytes (source-format dependent). Pickle (not stable across versions).
- **Rationale**: Independent of the storage format; the same bars from any source give the same hash. Pure stdlib,
  so it lives in the domain.
- **Cost of reversal**: MEDIUM — changing the format re-pins every entry and invalidates old references.

### D-3: OOS access needs certification mode, `SHADOW_CERTIFIED`, and a clock on or after 2027-01-01

- **Decision**: `assert_oos_access_allowed` raises `OOSDataLeakageError` for an OOS entry unless all three hold:
  `certification_context()` is active, the lifecycle state is `SHADOW_CERTIFIED` (the state the one-shot OOS test
  advances from, pre-registration §7), and `now` is after the OOS window end.
- **Alternatives**: Certification mode alone (today's `DataSplitEnforcer`; a bool that ignores the lifecycle and the
  date gate). State alone (no protection against an accidental read from a certified process).
- **Rationale**: Pre-registration §4 discipline gate and §7; ADR-014.
- **Cost of reversal**: LOW.

### D-4: The manifest's split windows must equal the signed pre-registration's

- **Decision**: `assert_manifest_matches_preregistration` compares experiment id and every split window with
  `PreRegistration.data_windows()` and raises on any difference; the backtest driver calls it before loading.
- **Rationale**: The manifest encodes the boundaries (issue scope) without becoming a second source of truth.
- **Cost of reversal**: LOW.

## Requirements

### R-1: Hash mismatch fails loudly

- **A-1.1**: `load_pinned_bars` raises `DatasetHashMismatchError` naming the dataset id, expected and actual hash
  and row counts when any bar differs from the pinned entry.

### R-2: OOS refused outside certification

- **A-2.1**: Loading a range that touches an OOS entry raises `OOSDataLeakageError` unless D-3's three conditions
  hold; the OOS bars are not hashed or returned.

### R-3: Unpinned ranges refused

- **A-3.1**: Loading a range that needs a split with no entry for that pair and interval raises
  `DatasetNotPinnedError`.

### R-4: Backtest reports reference the manifest

- **A-4.1**: `run_calibration.py` output JSON has `datasets: [{dataset_id, content_sha256, row_count}]`.

### R-5: Tests per ADR-007

- **A-5.1**: `uv run pytest tests/unit -k "dataset_manifest or pinned_dataset or data_manifest"` passes; domain
  ≥ 95 %, application ≥ 90 %, adapter ≥ 85 % line coverage.

## Design

```text
src/hermes/domain/market_data/dataset_manifest.py   new
src/hermes/domain/errors.py                          + 2 errors
src/hermes/ports/dataset_manifest.py                 new
src/hermes/adapters/data_manifest/{__init__,json_file}.py  new
src/hermes/application/strategy_protocol/pinned_dataset.py new
scripts/data/build_dataset_manifest.py               new
scripts/backtest/run_calibration.py                  load via load_pinned_bars
docs/experiments/swing-mvp1/data-manifest.json       new (Train + Validation, 3 pairs x 3 intervals)
```

`load_pinned_bars(source, manifest, pair, interval, start, end, *, state, now) -> PinnedBars` finds the split windows
that intersect `[start, end)`, requires an entry for each, checks OOS access before reading anything, streams the
source once, collects each entry's bars, verifies count and hash, and returns the bars in `[start, end)` with the
entries used.

Manifest JSON (`schema_version` 1):

```json
{
  "schema_version": 1,
  "experiment_id": "swing-mvp1-v1",
  "splits": {"train": {"start": "...", "end": "..."}, "validation": {...}, "oos": {...}},
  "datasets": [
    {"dataset_id": "klines/BTCUSDT/4h/train", "pair": "BTC/USDT", "interval": "4h", "split": "train",
     "source": "binance-vision", "row_count": 0, "content_sha256": "..."}
  ]
}
```

## Risks

- **The archive streams past the Validation end.** `BinanceHistoricalAdapter.stream_bars` reads one monthly zip at a
  time and the loader stops at the first bar past the last needed window. The adapter therefore parses the first OOS
  month file, and one OOS bar reaches the loader, which discards it unhashed. The old `_load_bars` did the same.
- **Re-ingest changes a pinned dataset.** Intended: the backtest fails until the operator re-pins and records why
  in the lab notebook.
- **Overlap with #313.** #313 rewrites the backtest driver; this change touches only its bar loading and report
  payload.
